# Сборка и выпуск cs2prak

Пошагово, своими руками. Ничего из этого не автоматизировано намеренно —
каждый шаг видно, и на любом можно остановиться.

Репозиторий: `Sevelinish/cs2Prak`, ветка `main`.

---

## 0. Что нужно на машине

- Python 3.11 с зависимостями из `requirements.txt`
- PyInstaller
- `make_release.py` в корне проекта

`make_release.py` намеренно не в репозитории (правило в `.gitignore`).
Если файла нет на диске — достаньте из истории:

```bash
git show 27b52a3:make_release.py > make_release.py
```

---

## 1. Поднять версию

`app.py`, строка 53:

```python
APP_VERSION = '1.1.6'
```

Версия обязана совпадать с будущим тегом без `v`. Проверить:

```bash
grep -n "APP_VERSION = " app.py
```

**Про нумерацию.** Версии сравниваются как кортеж чисел: `1.1.10` больше
`1.1.9`, это нормально. Но `1.1.41` больше `1.1.5`, поэтому такой номер
сжигает весь диапазон `1.1.6`–`1.1.40` — после него они станут «прошлым».

## 3. Коммит и пуш

```bash
git add -A
```

```bash
git commit -m "1.1.6: краткое описание"
```

```bash
git push origin main
```

Если пуш отклонили с `non-fast-forward` — на GitHub есть коммит, которого нет
у вас:

```bash
git pull --rebase origin main
```

потом снова `git push origin main`. `--force` не нужен: он сотрёт чужой коммит.

---

## 4. Сборка

```bash
python -m PyInstaller --noconfirm cs2prak.spec
```

3–5 минут, результат — `dist/cs2prak/` (`cs2prak.exe` + `_internal/`), ~400 МБ.

---

## 5. Положить рядом карты

`maps/` нет в spec, PyInstaller её не копирует, а без неё превью карт пустые:

```bash
python -c "import shutil; shutil.copytree('maps','dist/cs2prak/maps',dirs_exist_ok=True); print('maps ok')"
```

---

## 6. Пакет обновления

```bash
python make_release.py 1.1.6 dist/cs2prak release_assets --no-legacy
```

Появятся `release_assets/manifest.json` и `update.zip` (~13 МБ).

**Прочитайте список файлов, который он напечатает.** Там должны быть
`cs2prak.exe`, `_internal/templates/index.html` и файлы из `_internal/static/`.
Если фронтенда нет — дальше не идите: ровно на этом сломался релиз 1.1.2.

`--no-legacy` даёт только бандл вместо ~90 отдельных файлов. Безопасен, пока
все опубликованные релизы 1.1.3 и новее — они умеют читать бандл.

---

## 7. Полный установщик

Строго после шага 6: `make_release.py` очищает папку перед работой.

```bash
python -c "import shutil; print(shutil.make_archive('release_assets/cs2prak-1.1.6','zip','dist','cs2prak'))"
```

В `release_assets/` должно остаться ровно три файла:

| файл | для кого |
|---|---|
| `manifest.json` | апдейтер: хеши обновляемых файлов |
| `update.zip` | апдейтер: качает архив, распаковывает только изменившееся |
| `cs2prak-1.1.6.zip` | новые пользователи, ручная установка |

## 9. Проверка

```bash
curl -s https://api.github.com/repos/Sevelinish/cs2Prak/releases/latest
```

Нужны `"tag_name": "v1.1.6"` и три ассета. Это тот же запрос, который делает
приложение.

Живая проверка: запустите предыдущую сборку — она должна предложить
обновление, скачать ~13 МБ и перезапуститься уже новой версией.

## Перевыпуск того же номера

Если релиз уже опубликован, а в нём нашлась ошибка, можно перевыпустить под тем
же тегом — апдейтер это поддерживает: гейт по версии пропускает равные номера,
дальше сверяются SHA-256 файлов, и изменившийся `cs2prak.exe` даёт обновление.

Порядок: удалить релиз на GitHub → удалить тег → собрать заново → создать релиз
с тем же тегом.

```bash
git push origin --delete v1.1.6
```

```bash
git tag -d v1.1.6
```

Цена: кто успел скачать полный архив до перевыпуска, останется со сломанной
сборкой и узнает об этом только при следующей проверке обновлений. Если
пользователи уже есть — надёжнее просто выпустить следующий номер.

---

## Три грабли

**Тег без `v`.** Тег обязан быть `v1.1.6`, иначе сравнение версий не сработает.

**Карты и радары не обновляются никогда.** `is_updatable()` в `make_release.py`
пропускает `maps/` и `_internal/static/radars/` — это 16 из 16.2 МБ картинок,
исключены ради размера релиза. Если поменяете радар или превью карты,
инкрементальное обновление его не принесёт: нужна полная переустановка, и об
этом стоит написать в описании релиза.

**Новый тип ассета.** В `is_updatable()` перечислены расширения
(`.js .css .svg .png .jpg .ico`) внутри `_internal/static/`. Добавите шрифты
или что-то ещё — внесите расширение туда вручную, иначе файлы не доедут.
